# Чек на удачу

Тестовое задание. Промо-акция: пользователь регистрирует кассовый чек, модератор проверяет.

Стек: Python 3.12, Django 5.0, PostgreSQL 16, Docker, vanilla JS.

## Как запустить

```bash
git clone https://github.com/MikasaAl4naya/receipt-promo && cd receipt-promo
cp .env.example .env
docker compose up --build
```

В отдельном терминале создать суперпользователя (он же модератор):

```bash
docker compose exec web python manage.py createsuperuser
```

Сайт: http://localhost:8000  
Админка: http://localhost:8000/admin/

Тесты:

```bash
docker compose exec web python manage.py test receipts
```

## Что сделано

Обязательная часть:

- модель чека: ФН, ФД, ФП, дата и время покупки, сумма, статус, причина отказа, пользователь, дата регистрации
- форма регистрации с серверной валидацией: дата входит в период акции (даты в .env), сумма не меньше 1000 руб., уникальность ФН+ФД+ФП с понятным сообщением об ошибке
- личный кабинет со списком своих чеков, пагинация по 10
- отправка формы через fetch, ответ сервера отображается на странице без перезагрузки
- клиентская валидация до отправки: обязательные поля, форматы, ошибки рядом с полями
- модератор работает через стандартную админку
- GET /api/receipts/ возвращает чеки текущего пользователя в JSON

Сверх задания:

- поле для строки из QR-кода чека, парсит t/s/fn/i/fp и заполняет форму
- загрузка фото чека с проверкой формата (JPEG, PNG, WebP) и размера (макс. 5 МБ)
- статус в кабинете обновляется без перезагрузки, опрос раз в 15 секунд
- выгрузка принятых чеков в CSV из админки
- 12 тестов на валидацию: сумма, границы дат, форматы реквизитов, дубликаты

## Спорные места

**Часовой пояс и период акции.** Сравниваю только дату, без времени. Если на чеке написано 31 марта, чек принимается вне зависимости от часового пояса пользователя. Акция формулируется как "покупка с X по Y", то есть имеется в виду дата на чеке, а не UTC-метка.

**Повторная подача отклонённого чека.** Запрещена. Уникальность ФН+ФД+ФП держится на уровне БД, статус чека роли не играет. Если чек отклонили и пользователь пытается подать его снова, он увидит сообщение с текущим статусом. Это закрывает очевидный способ обойти модерацию. Если отклонение было ошибочным, пользователь пишет в поддержку.

**API без DRF.** Один GET-эндпоинт не требует djangorestframework, хватает обычного JsonResponse.
